F91 — /phase0/'s skip link was invisible: cream text on a cream chip, 1.00:1

Accessibility · HIGH · https://imjustdex.com/phase0/ · FIXED + RETESTED

The skip link is the first focusable element on the page — the control a keyboard user hits before anything else. On /phase0/ it computed color: rgba(243,240,232,.82) on its own background: var(--ink) cream chip. That is 1.00:1, the worst ratio this ledger has ever recorded, and the only finding to date where the text is not merely low-contrast but literally invisible. A sighted keyboard user sees the red focus ring land on a blank cream box.

It is not a colour bug. --bg resolves correctly to #060606 at every level of the chain. It is a specificity bug — three rules set colour on this element:

RuleSpecificitySheet
a { color: inherit }(0,0,1)tokens.css
.skip-link { color: var(--bg) }(0,1,0)shell.cssthe intended rule
.phase0 a { color: inherit }(0,1,1)phase0.csswins — hands the chip back body cream

Scope is exactly one page. /brand/, the other bespoke-CSS surface, carries no blanket a rule and measured clean.

Why every prior run missed it: the skip link rests at left:-999px. Any sweep that filters to on-screen elements never measures it. This run caught it by measuring every element with layout geometry regardless of viewport position — a deliberate widening after F85 showed that resting states are where defects hide.

Fix: hardened the shell rule to .skip-link, .skip-link:link, .skip-link:visited — specificity (0,2,0), which beats (0,1,1) on the class/pseudo-class count regardless of source order. Repaired in the shared sheet rather than in phase0.css on purpose, so any future bespoke surface that adds a blanket link rule inherits the immunity. That is the F87 lesson applied forward: fix the shared sheet, not the one surface that happened to break.

Retest: build clean, 19 pages, all 21 built pages on shell.css?v=phase36. Cascade verified empirically, not by reasoning — I inserted the exact committed selector into the live shell.css CSSOM (CSP blocks <style> injection but not CSSOM mutation of an already-loaded same-origin sheet) and re-measured: /phase0/ 1.00:1 → 17.79:1, colour flipping to the intended rgb(6,6,6) on cream. Regression-checked on the two surfaces most likely to be disturbed — homepage and /brand/ — both no-op.

Two false positives, caught before filing

White-on-cream at 1.06:1 on the homepage plates — not real

Method · light mode · dismissed

The light-mode sweep initially flagged h2.plate-title.inverse and p.plate-deck at 1.06:1 — which would have been catastrophic, essentially invisible headlines on your archive. Both are false. Those plates carry an ::after linear-gradient(to top, rgba(0,0,0,.78) …) scrim, so the white text sits on a dark overlay, not on the cream plate colour. Confirmed visually in a light-mode screenshot before dismissing.

Two compounding bugs in my own sweep produced it, and both are now fixed: the compositor walked background-color only and ignored pseudo-element layers; and selector-level dedupe merged image and non-image plates under the same class string, so a passing element inherited a failing element's number. Same lesson as F84 — resolve the painted surface, never infer it from an ancestor's declarations.
